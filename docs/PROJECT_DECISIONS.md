# CookLog Project Decisions

이 문서는 플랫폼 공통 제품 및 저장소 운영 결정사항을 관리합니다. 플랫폼별 기술 결정은 각 앱 폴더의 `docs/DECISIONS.md`에 기록합니다.

## 2026-07-31 - 루트 Agent 안내는 세부 정책을 복제하지 않고 Source of Truth를 연결

- 상태: 확정
- 결정: 루트 `agents.md`에는 역할, 문서 탐색 순서, 충돌 우선순위와 책임 경계만 유지합니다.
- 제품 세부사항: 기능 범위, 현재 진행률, 기술 선택과 UI 원본 위치는 담당 Source of Truth에서만 관리합니다.
- 플랫폼 문서: 실행 Task와 최신 제품 Source of Truth가 플랫폼 안내보다 우선하며 충돌을 발견하면 문서 정합성 Task로 보고합니다.
- 이유: 제품 정책이 바뀔 때 여러 안내 문서의 복제 내용이 서로 달라지는 문제를 줄이기 위해서입니다.

## 2026-07-29 - 첫 공개 출시 STT는 Apple 기기 내 처리를 기본으로 사용

- 상태: 확정
- 출시 기본값: 첫 공개 출시의 10초 기록은 지원되는 Apple 기기의 기기 내 STT로 텍스트를 생성합니다.
- 원격 경로: 유료 원격 STT는 같은 공통 인터페이스 뒤의 교체형 adapter로 유지하되 기본 설정은 비활성화합니다.
- 전환 금지: 기기 내 STT가 지원되지 않거나 실패해도 원격 STT로 자동 fallback하지 않습니다. 사용자의 음성을 별도 승인 없이 Backend나 원격 STT 제공업체로 보내지 않습니다.
- 실패 처리: 같은 기기 내 adapter의 복구 가능한 기술 오류는 최대 1회 재처리할 수 있습니다. 이후에도 실패하면 새 STEP을 만들지 않고 기존 기록을 보존한 채 `다시 기록하기`를 제공합니다.
- 오프라인: 기기 내 STT를 사용할 수 있는 지원 환경에서는 새 10초 기록과 STEP Preview 생성에 인터넷 연결을 요구하지 않습니다. `AI 정리하기`는 계속 인터넷 연결이 필요합니다.
- 출시 게이트: 지원 기기·OS·한국어 인식 품질 또는 구현 안정성이 최소 출시 기준을 충족하지 못하면 원격 adapter를 자동 활성화하지 않고 Product Owner가 지원 범위 조정, 출시 연기 또는 원격 STT 도입을 별도로 결정합니다.
- 비용 근거: 월 활성 설치 1,000개, 설치당 월 4회 기록, 기록당 10초 clip 6개, 분당 USD 0.016, 예산 환율 KRW 1,400과 10% buffer를 적용하면 원격 STT 단독 비용은 월 KRW 98,560으로 추정됩니다. 실제 측정값이나 확정 견적이 아니므로 실제 사용량과 필요성이 확인되기 전에는 고정 운영비를 부담하지 않습니다.
- 기존 개발 산출물: 개발 Agent가 별도 브랜치에서 작성한 원격 STT 비교·아키텍처 문서는 보존하되 이 결정의 공식 근거나 승인된 출시 정책으로 간주하지 않습니다. 향후 원격 adapter 검토 자료로만 사용할 수 있습니다.

## 2026-07-29 - 첫 공개 출시 Roadmap과 Team Mission Task 재구성

- 상태: 확정
- 목표: iOS에서 실제 Apple 기기 내 STT, 온라인 AI와 로컬 TTS·핸즈프리를 포함한 첫 App Store 공개 출시를 Mission Clear로 정의합니다.
- 단계: 제품 기준 고정, 병렬 Foundation, 제품 기능 구현, TestFlight·App Store 통합의 네 단계로 진행합니다.
- 병렬 Foundation: 확정 디자인, XCTest·CI와 Backend AI 계약·foundation을 의존성이 허용하는 범위에서 병렬 진행합니다. 원격 STT adapter는 기본 비활성 확장 경계로만 유지합니다.
- iOS 구현: 로컬 상태·화면 적용과 실제 STT, AI, Audio Guide를 분리된 상위 Task로 관리합니다.
- 폐기: 구형 Mock UI를 다시 검증하는 `T-20260728-001`은 이후 구현·최종 게이트와 중복되어 취소하고 유효 항목을 `T-20260728-003`, `T-20260728-009`에 통합합니다.
- 수정: `T-20260728-003`, `005`, `006`, `009`를 각각 로컬 제품 구현, AI·선택형 원격 STT 계약, gateway foundation, 최종 공개 출시 통합 Task로 재정의합니다.
- 신규: Backend production `T-20260729-003`, iOS 기기 내 STT `004`, AI Review integration `005`, Audio Guide·handsfree `006`을 제안 상태로 등록합니다.
- 승인 경계: Team Lead가 하위 Task로 분해하고 Product Owner가 승인하기 전에는 실행하지 않습니다. 외부 provider·배포·TestFlight·App Store 제출은 별도 승인합니다.
- 제외: 수익화 동결 Workstream과 Android는 Core v1 공개 출시 Critical Path에서 제외합니다.
- 이유: 오래된 Mock 검증과 모호한 실서비스 준비 Task를 제거하고 각 Team이 추가 구두 설명 없이 실행·검증 가능한 책임 단위로 전환하기 위해서입니다.

## 2026-07-29 - 온라인 장애는 로컬 기능을 유지하고 사용자가 직접 재실행

- 상태: 확정
- 오류 구분: 마이크·녹음·기기 내 STT, 인터넷 연결, CookLog Backend, 외부 AI와 로컬 저장 문제를 내부적으로 구분하되 사용자에게 내부 코드나 업체명을 노출하지 않습니다.
- STT 실패: 같은 기기 내 adapter의 1회 자동 재처리 후에도 실패하면 원격 STT로 전환하지 않고 새 STEP을 만들지 않습니다. 음성을 삭제하고 기존 기록을 보존한 채 `다시 기록하기`를 제공합니다.
- AI 실패: 기존 STEP을 보존하고 자동 재실행 없이 `다시 정리하기` 또는 `기록으로 돌아가기`를 제공합니다.
- 로컬 사용: 온라인 장애 중에도 진행·완료 레시피, 로컬 검색, 로컬 저장과 Audio Guide를 계속 사용합니다.
- 복구 행동: STT 실패나 온라인 AI 서비스 복구 후에도 실패한 행동을 자동 실행하거나 화면을 자동 전환하지 않고 사용자가 다시 시작합니다.
- 안내: 현재 화면과 Home의 짧은 상태만 사용하고 첫 출시에서는 장애 복구 푸시와 별도 서비스 상태 페이지를 제공하지 않습니다.
- 지원: `앱 정보`에 이메일 문의, 개인정보처리방침, 이용약관과 데이터 보관 안내를 제공합니다. 실시간 채팅과 24시간 고객지원은 제외합니다.
- 문의 개인정보: 음성, STT 본문, 레시피 내용과 검색어를 문의에 자동 첨부하지 않고 사용자가 선택한 앱 버전과 비콘텐츠 진단 정보만 포함할 수 있습니다.
- 이유: 외부 온라인 서비스 장애가 개인 레시피의 조회와 재사용까지 차단하지 않게 하면서 예측하기 어려운 자동 재실행과 중복 요청을 막기 위해서입니다.

## 2026-07-29 - 첫 공개 출시는 내부 1인·실기기 1대의 최소 품질 게이트 적용

- 상태: 확정
- 검증 규모: 외부 테스터를 필수로 요구하지 않고 내부 검증자 1명이 실제 지원 iPhone 최소 1대에서 수행합니다.
- 핵심 흐름: 기록부터 STT, AI Review, 저장, 앱 재실행과 Audio Guide까지 3회 연속 완료해야 합니다.
- STT 최소 표본: 일반 실내 5회와 조리 소음 환경 5회 중 핵심 행동이 이해 가능한 STEP Preview가 합계 8회 이상이어야 합니다.
- AI 최소 표본: 서로 다른 기록 5개가 최초 요청 또는 1회 수동 재실행 안에 모두 Review로 진입하고 기록 손실이 없어야 합니다. 안전 관련 정보 창작은 0건이어야 합니다.
- 핸즈프리 최소 표본: 7개 명령을 조리 소음 환경에서 각각 1회 성공시키고 인식 실패 후 버튼 fallback을 1회 확인합니다.
- 복구 확인: STEP 자동 저장, AI Review 임시 저장, AI 처리 중 재실행, 오프라인 안내와 AI 실패 재실행을 각각 1회 확인하며 데이터 손실을 허용하지 않습니다.
- 결함 기준: 출시 빌드와 필수 CI가 통과하고 미해결 P0·P1 결함이 0건이어야 합니다.
- 해석: 이 기준은 제한된 인력에서 치명적인 출시 결함을 막기 위한 최소 게이트이며 통계적 품질 검증을 대신하지 않습니다. 실제 서비스 지표로 출시 후 보강합니다.
- 이유: 주변 테스터 확보를 출시 선행조건으로 만들지 않으면서 핵심 기록과 재사용 흐름의 중단·데이터 손실은 차단하기 위해서입니다.

## 2026-07-29 - 음성·레시피 콘텐츠는 처리에 필요한 최소 기간만 서버에서 사용

- 상태: 확정
- 첫 출시 음성 삭제: Apple 기기 내 STT에 사용하는 앱 내부 임시 음성만 허용합니다. 성공, 최종 실패 또는 같은 adapter의 1회 자동 재처리 종료 후 즉시 삭제하고 비정상 잔존 방지 TTL을 최대 1시간으로 제한합니다. 첫 출시 기본 경로에는 Backend 음성 사본이 없습니다.
- 향후 원격 adapter: 별도 제품 정책과 비용 승인을 받아 원격 STT를 활성화할 때만 Backend 임시 음성에 즉시 삭제·최대 1시간 TTL을 적용합니다.
- 콘텐츠 저장: STT 본문, STEP Preview, AI 입력과 AI 결과를 운영 DB·분석·오류 로그에 영구 저장하지 않습니다.
- AI 결과 복구: 앱 재실행 복구에 필요한 암호화된 결과 캐시는 앱 수신 확인 즉시 삭제하고 확인되지 않아도 최대 24시간 뒤 삭제합니다.
- 운영 메타데이터: 요청 ID, 시각, 성공 여부, 오류 범주, 지연시간과 사용량·비용처럼 사용자 콘텐츠가 없는 정보만 최대 30일 보관한 뒤 삭제하거나 비식별 통계로 집계합니다.
- 분석 제외: 음성, 레시피 제목·재료·단계·메모, 검색어, STT 본문과 AI 결과 본문을 분석 이벤트와 오류 로그에 남기지 않습니다.
- 외부 제공업체: 모델 학습 사용을 비활성화하고 가장 짧은 보관 설정을 적용합니다. 실제 보관·학습·처리 조건은 출시 전에 검증해 개인정보처리방침에 공개합니다.
- 승인 경계: 제공업체의 실제 조건이 이 기준보다 긴 보관을 요구하면 Product Owner의 별도 승인 없이는 출시 경로로 사용하지 않습니다.
- 이유: 개인 레시피 콘텐츠의 노출 범위를 최소화하면서 AI 요청 복구, 장애 분석과 비용 통제에 필요한 운영 정보는 확보하기 위해서입니다.

## 2026-07-29 - 첫 출시는 로컬 저장만 제공하고 자체 백업은 제외

- 상태: 확정
- 저장 범위: 계정 없이 진행 기록과 완료 레시피를 사용 중인 기기 내부에 저장합니다.
- 데이터 유지: 정상 앱 종료와 앱 업데이트에는 기존 데이터를 유지하며 사용자가 삭제하지 않은 기록을 기간·개수에 따라 자동 삭제하지 않습니다.
- 복구 경계: 앱 삭제, 기기 초기화·분실 또는 로컬 저장소 손상 시 데이터가 유실될 수 있으며 CookLog 자체 복구를 보장하지 않습니다.
- 운영체제 백업: 운영체제의 기기 백업으로 복원될 가능성이 있더라도 CookLog가 백업 완료나 복구 성공을 약속하지 않습니다.
- 사용자 안내: 상시 경고 배너는 사용하지 않고 사용자가 확인할 수 있는 `데이터 보관 안내`에 로컬 저장 범위와 유실 가능성을 명확히 표시합니다.
- 출시 제외: 계정 기반 클라우드 백업·기기 간 동기화와 레시피 내보내기는 첫 출시에서 제외합니다.
- 후속: 여러 기기 사용, 데이터 복구와 직접 보관 수요가 확인되면 클라우드 동기화와 레시피 내보내기를 각각 평가합니다.
- 이유: 로그인 없이 빠르게 기록하는 첫 출시 범위를 유지하면서 실제로 제공하지 않는 데이터 복구를 사용자에게 약속하지 않기 위해서입니다.

## 2026-07-29 - 기록부터 오디오 가이드까지 제품 UX 정책 확정

- 상태: 확정
- 10초 기록: MVP는 `10초 기록` 고정과 자동 종료를 사용합니다. 조기 종료는 현재 제공하지 않고 향후 확장 가능성만 유지합니다.
- 음성 보관: 음성은 STT 입력 도구일 뿐이며 성공 또는 복구 가능한 기술 오류의 1회 자동 재처리 후 삭제합니다. CookLog가 보존하는 기록은 텍스트입니다.
- STEP Preview: 10초 기록 1개당 원문 중심 Preview 1개를 녹음 시간순으로 표시합니다. 직접 수정·재배열은 제공하지 않고 스와이프 삭제와 짧은 되돌리기를 제공합니다.
- STEP 저장: Preview 추가·삭제는 자동 저장하고 여러 진행 레시피를 허용합니다.
- AI 원칙: AI는 기록을 구조화할 뿐 기록에 없는 재료, 수량, 시간, 온도와 조리법을 창작하지 않습니다. 근거가 있는 값만 `AI 추정`으로 채우고 근거가 없거나 안전과 관련된 값은 누락으로 둡니다. 추정값은 필드별로 확인하며 일괄 확인하지 않고, 확인되지 않은 표시는 저장 후에도 유지합니다.
- AI Review 저장: 최초 AI 초안은 기본 저장하고 사용자 수정은 `임시 저장` 버튼으로 저장합니다. 버튼을 눌러도 화면에 머무르며 토스트만 표시합니다. `레시피 저장`은 최종 완료 전환입니다.

## 2026-07-28 - develop 통합과 main 안정·릴리즈 브랜치 분리

- 상태: 확정
- 결정: 일반 Task는 최신 `develop`에서 분기하고 `develop` 대상 PR로 병합합니다. `main`은 통합 검증을 통과한 릴리즈 가능한 상태만 유지하며 `develop -> main` 승격 PR 또는 승인된 `hotfix/*` PR만 받습니다.
- 완료 경계: 팀별 하위 Task는 독립 검증과 `develop` 병합 후 Team Lead가 완료합니다. 상위 제품 Task와 릴리즈 목표는 필수 하위 Task 완료, cross-team 통합 QA, Product Lead 수용 검토와 Product Owner의 `main` 승격 승인을 거칩니다.
- hotfix: `main`에서 생성해 `main`에 병합하고 동일 변경을 `develop`에 즉시 backport합니다.
- 보호 원칙: `main`과 `develop` 직접 commit, push, force push를 금지합니다.
- 이유: 디자인·iOS·Backend와 문서 Task를 병렬 운영하면서도 불완전한 통합 상태가 `main`에 바로 유입되지 않도록 하기 위해서입니다.
- 영향: GitHub 기본 작업 브랜치와 신규 세션 기준은 `develop`이며 `main`은 안정·릴리즈 기준입니다.
