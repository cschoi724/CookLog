# CookLog Product Charter v2

최종 업데이트: 2026-07-29

이 문서는 CookLog의 제품 방향을 빠르게 확인하는 한 장짜리 지침입니다. 상세 기능·상태·오류 정책은 `CookLog_PRD_v2.md`, 출시 단계와 Task 의존성은 `CookLog_ROADMAP.md`를 기준으로 합니다.

## 제품 정의

CookLog는 사용자가 요리 중 남긴 짧은 음성 기록을 개인 레시피로 정리하고, 다음 요리에서는 단계별 오디오 가이드로 다시 사용할 수 있게 해주는 개인 요리 기록 앱입니다.

기존 레시피 앱이 다른 사람의 레시피를 소비하는 데 집중한다면 CookLog는 사용자의 실제 요리를 가장 쉽게 기록하고 다시 재현하는 데 집중합니다.

## 제품 미션

사용자가 우연히 잘 만든 요리를 잊지 않고, 다음에도 같은 방식으로 다시 만들 수 있게 합니다.

```text
요리
-> 10초 음성 기록 반복
-> STEP Preview 축적
-> AI 정리
-> 사용자 검토와 저장
-> 개인 레시피
-> 단계별 Audio Guide로 재사용
```

## Core Value

- 기록: 요리 중 10초 단위로 빠르게 말합니다.
- 축적: 텍스트 기반 개인 레시피를 기기 안에 보관합니다.
- 재사용: 화면과 Audio Guide로 같은 요리를 다시 만듭니다.

AI와 음성은 제품 목적이 아니라 기록과 재사용을 쉽게 만드는 수단입니다.

## 첫 공개 출시의 제품 약속

- 10초 기록 1개는 STT 원문 중심 STEP Preview 1개가 됩니다.
- 여러 진행 레시피를 보존하고 현재 단계부터 이어갑니다.
- AI는 사용자의 기록을 구조화하되 기록에 없는 사실을 창작하지 않습니다.
- 사용자는 AI Review에서 제목, 재료와 단계별 조리 순서를 검토·수정합니다.
- 완료 레시피는 수정·삭제·검색하고 Audio Guide로 다시 사용할 수 있습니다.
- Audio Guide는 버튼을 항상 제공하고 사용자가 시작한 핸즈프리 명령을 함께 지원합니다.
- 온라인 STT·AI 장애가 로컬 레시피 조회와 Audio Guide를 차단하지 않습니다.
- 첫 출시는 계정과 자체 클라우드 백업 없이 기기 내부 저장을 사용합니다.

## 첫 공개 출시에서 하지 않는 것

- 로그인과 회원가입
- 공유, 커뮤니티와 소셜 기능
- 블로그·유튜브·OCR Import
- AI 챗
- 클라우드 동기화와 자체 복구
- 레시피 버전 기록과 삭제 복구
- 자동 로컬 STT fallback
- 수익화 활성화

수익화는 동결된 별도 제품 Workstream으로 유지하고 Core v1 출시를 차단하지 않습니다.

## Product Principles

1. 가장 먼저 최적화할 행동은 레시피 작성이 아니라 요리 기록입니다.
2. 10초 기록은 고정 시간으로 자동 종료합니다.
3. 음성은 입력 도구이며 보존되는 사용자 기록은 텍스트입니다.
4. STEP Preview는 원문 기록이고 AI 구조화는 `AI 정리하기`에서만 수행합니다.
5. AI는 근거가 있는 정보만 구조화하며 추측은 표시하고 안전 관련 정보는 창작하지 않습니다.
6. 진행 기록은 명시적 삭제 전까지 보존하고 마지막으로 성공한 저장 시점에서 복구합니다.
7. 완료 저장은 사용자의 명시적 행동이며 실패한 저장을 완료로 표시하지 않습니다.
8. 버튼은 항상 사용할 수 있고 핸즈프리는 첫 공개 출시의 핵심 재사용 경험입니다.
9. 온라인 장애 중에도 로컬 기록과 Audio Guide를 사용할 수 있어야 합니다.
10. 제공하지 않는 백업·복구·정확도를 사용자에게 약속하지 않습니다.
11. 음성·레시피 콘텐츠는 처리에 필요한 최소 시간만 서버에서 사용합니다.
12. 출시 범위는 실제 사용자 가치와 데이터 손실 위험을 기준으로 우선순위를 정합니다.
