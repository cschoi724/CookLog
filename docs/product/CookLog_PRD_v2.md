## 1. Product Vision

CookLog는 사용자가 요리 과정을 가장 쉽게 기록하고, 나중에 가장 쉽게 다시 재현할 수 있도록 돕는 개인 레시피 저장소입니다.

기존 레시피 앱이 레시피를 소비하는 데 집중했다면, CookLog는 레시피를 생성하고 축적하는 데 집중합니다.

## 2. Problem Statement

사용자는 우연히 맛있게 만든 요리를 자주 잊어버립니다. 하지만 대부분 기록하지 않습니다.

이유는 간단합니다. 기록하는 과정이 너무 귀찮기 때문입니다.

기존 레시피 앱은 다음과 같은 복잡한 과정을 요구합니다.

- 제목 입력
- 재료 입력
- 수량 입력
- 단계 입력

결과적으로 사용자는 기록하지 않습니다.

## 3. Product Goal

사용자가 요리를 기록하는 행위를 부담 없이 수행하도록 만듭니다.

목표는 레시피 작성이 아니라 요리 기록입니다.

## 4. Target User

Primary Persona: 20~30대 자취생

특징:

- 요리를 자주 하지 않습니다.
- 레시피를 자주 검색합니다.
- 맛있게 만든 요리를 잊어버립니다.
- 요리 기록 습관이 없습니다.
- 복잡한 입력을 싫어합니다.

## 5. Core Experience

### 기존 방식

요리 -> 기억 -> 잊어버림

### CookLog 방식

요리 -> 10초 기록 -> 레시피 생성 -> 저장 -> 재사용

## 7. User Flow

Home
-> 요리 기록 시작
-> 10초 기록
-> STEP Preview 생성
-> 10초 기록 반복
-> AI 정리하기
-> 레시피 검토
-> 임시 저장 또는 레시피 저장
-> 레시피 상세
-> 오디오 가이드

첫 사용 안내:

- 앱 첫 실행에서 여러 장의 별도 온보딩 화면을 표시하지 않고 Home으로 바로 진입합니다.
- 첫 기록에서 `10초씩 요리 과정을 말해보세요`를 한 번 안내합니다.
- 첫 AI Review에서 `저장 전에 내용을 확인하고 수정할 수 있어요`를 한 번 안내합니다.
- 첫 핸즈프리 시작에서 `말로 다음·이전·멈춤을 조작할 수 있어요`를 한 번 안내합니다.
- 안내는 현재 행동을 막지 않는 짧은 맥락형 안내로 제공하고 반복 노출하지 않습니다.

## 8. Cooking Log Specification

목표: 사용자가 레시피를 작성하지 않도록 합니다. 사용자는 음성으로만 기록합니다.

기록 방식:

1. 사용자가 10초 기록 버튼을 선택합니다.
2. 10초 동안 음성을 녹음합니다.
3. STT로 텍스트를 변환합니다.
4. STT 결과를 STEP Preview로 생성합니다.

기록 정책:

- 10초는 MVP의 고정 기록 시간이며 10초 후 자동 종료합니다.
- 조기 종료는 현재 제공하지 않되 향후 추가할 수 있도록 구조적 확장 가능성만 유지합니다.
- 시간 연장, 녹음 일시중지·재개, STT 취소·수동 재시도는 현재 범위에서 제외합니다.
- 원본 음성은 입력 도구일 뿐이며 장기 보관하지 않습니다.
- STT 성공 후 원본 음성을 삭제합니다.
- 네트워크·업로드·STT 서비스 오류처럼 복구 가능한 기술 오류는 원본을 임시 보관하고 1회 자동 재처리한 뒤 삭제합니다.

마이크 권한:

- 앱 첫 실행에서는 마이크 권한을 요청하지 않습니다.
- 사용자가 처음 `10초 요리 기록 시작`을 선택했을 때 사용 이유를 짧게 설명한 뒤 시스템 권한을 요청합니다.
- 권한을 거부해도 Home, 진행 기록, 완료 레시피 조회와 Audio Guide는 계속 사용할 수 있습니다.
- 거부된 상태에서 기록을 다시 시도하면 권한 필요 이유와 `설정으로 이동`을 제공합니다.
- 권한 안내를 닫으면 사용자가 보던 화면에 그대로 머무릅니다.

예시:

```text
사용자: "삼겹살 넣고 볶았어"
STEP 1: 삼겹살 넣고 볶았어

사용자: "양파 반 개 넣었어"
STEP 2: 양파 반 개 넣었어
```

STEP Preview 정책:

- 10초 기록 1개당 STEP Preview 1개를 생성합니다.
- STT 원문을 중심으로 표시하고 STT 엔진의 기본 문장부호 처리는 허용합니다.
- STEP Preview에서는 요약, 재작성, 추측 또는 단계 병합을 하지 않습니다.
- Preview는 녹음 시간순으로 고정하고 직접 수정이나 순서 변경을 지원하지 않습니다.
- 카드를 왼쪽으로 스와이프해 삭제하고 삭제 직후 짧은 `되돌리기`를 제공합니다.
- 잘못된 Preview는 삭제 후 다시 녹음하거나 다음 음성 기록으로 정정합니다.
- STEP 추가·삭제 시마다 텍스트 초안을 로컬에 자동 저장합니다.

STT 결과 정책:

- 첫 출시는 지원되는 Apple 기기의 기기 내 STT를 기본 실제 처리 경로로 사용합니다.
- 유료 원격 STT는 같은 공통 인터페이스 뒤의 교체형 adapter로 유지하되 기본 설정은 비활성화합니다.
- 기기 내 STT가 지원되지 않거나 실패해도 원격 STT로 자동 fallback하지 않고 음성을 Backend나 외부 제공업체에 전송하지 않습니다.
- 같은 기기 내 adapter의 복구 가능한 기술 오류는 최대 1회 재처리할 수 있습니다.
- 지원 기기·OS·한국어 품질 또는 구현 안정성이 최소 출시 기준을 충족하지 못하면 Product Owner가 지원 범위 조정, 출시 연기 또는 원격 adapter 도입을 별도로 결정합니다.
- 텍스트가 생성되면 STEP Preview를 만들고, 잘못 인식된 내용은 사용자가 삭제할 수 있게 합니다.
- 텍스트가 없거나 명확한 기술 오류가 발생했을 때만 실패로 처리합니다.
- 앱은 마이크 권한, 녹음, 기기 내 STT 지원 여부와 인식 오류를 내부 코드로 구분합니다. 원격 adapter가 비활성화된 첫 출시에서는 네트워크·업로드·외부 STT 오류를 기본 기록 경로에 포함하지 않습니다.
- 사용자에게는 내부 코드가 아니라 실패 원인과 다음 행동을 안내합니다.

오프라인 사용 범위:

- 지원 환경의 새 10초 음성 기록과 STEP Preview 생성
- 기존 STEP Preview와 진행 레시피 조회·편집
- 완료 레시피 조회·수정
- 로컬 TTS Audio Guide
- `AI 정리하기`는 인터넷 연결이 필요합니다.

## 9. A-Lite Strategy

실시간으로 레시피가 만들어지는 경험을 제공합니다. 하지만 실제 AI 레시피 구조화는 수행하지 않습니다.

STEP Preview는 STT 결과를 기반으로 생성됩니다.

AI는 `AI 정리하기` 시점에만 호출됩니다.

목적:

- 비용 절감
- 구현 난이도 감소
- 사용자 만족도 유지

## 10. AI Review Specification

`AI 정리하기` 실행 시 전체 STEP Preview를 분석합니다.

생성 결과:

- 레시피 제목
- 재료
- 조리순서
- 예상시간
- 메모

AI 구조화 원칙:

- AI는 사용자의 기록을 레시피 형태로 구조화하며 새로운 레시피를 창작하지 않습니다.
- 기록에 없는 재료, 수량, 시간, 온도와 조리법을 임의로 추가하지 않습니다.
- 제목은 핵심 재료와 조리법을 바탕으로 짧게 만들고 확인되지 않은 맛·스타일 표현을 붙이지 않습니다.
- 합리적인 근거가 있으면 가장 가능성 높은 값을 채우고 `AI 추정`으로 표시합니다.
- 근거가 없거나 안전과 관련된 값은 추측하지 않고 누락 상태로 둡니다.
- 필드는 `확정`, `AI 추정`, `누락` 상태를 가질 수 있습니다.
- `AI 추정`은 사용자가 확인하거나 수정할 때까지 유지하며, 확인하지 않아도 임시 저장과 최종 저장은 가능합니다.
- 사용자가 수정한 필드는 확정 상태가 됩니다.
- `AI 추정`은 필드별로 확인하거나 수정하며 전체 일괄 확인은 제공하지 않습니다.
- 확인되지 않은 `AI 추정` 표시는 저장 후 Recipe Detail에서도 유지합니다.
- 누락 값은 저장을 막지 않으며 Recipe Detail에서 표시를 생략할 수 있습니다.
- 명시적인 정정은 반영하고 애매한 반복이나 충돌은 확인 대상으로 남깁니다.

편집 정책:

- 사용자는 제목, 재료, 수량, 조리 단계, 예상 시간과 메모를 수정할 수 있습니다.
- 조리 순서는 한 개의 큰 문자열이 아니라 순서가 있는 단계 배열입니다.
- 단계마다 독립 입력 카드를 제공하고 번호는 시스템이 자동 부여합니다.
- 단계 추가·삭제·드래그 재배열을 지원하고 접근성을 위해 위·아래 이동도 제공합니다.
- 단계 삭제 직후 짧은 `되돌리기`를 제공합니다.

저장 정책:

- AI가 처음 만든 Review와 현재 단계는 기본 초안으로 저장합니다.
- 사용자 수정사항은 `임시 저장`을 눌렀을 때 저장합니다.
- 임시 저장 후 화면에 머무르고 `임시 저장되었습니다` 토스트만 표시합니다.
- 변경사항이 없어도 임시 저장 버튼을 사용할 수 있습니다.
- 마지막 임시 저장 이후 수정사항이 있는 상태에서 나가면 `임시 저장 후 나가기`, `저장하지 않고 나가기`, `계속 작성`을 제공합니다.
- 앱이 예기치 않게 종료되면 마지막 임시 저장 시점으로 복구합니다. 임시 저장 이력이 없으면 최초 AI Review 초안으로 복구합니다.
- `레시피 저장`을 누르면 진행 중 상태에서 최종 완료 레시피로 전환합니다.

최종 저장 실패 정책:

- 최종 저장의 필수 조건은 공백을 제외한 제목과 공백을 제외한 조리 단계 최소 1개입니다.
- 재료, 수량, 예상 시간과 메모는 누락돼도 저장할 수 있습니다.
- 재료명과 수량이 모두 비어 있는 행은 저장할 때 무시합니다.
- 재료명만 있는 행은 수량 없이 저장할 수 있습니다.
- 수량만 있고 재료명이 없는 행은 해당 행에 재료명 입력 안내를 표시합니다.
- 공백만 있는 조리 단계 카드는 저장할 때 제외합니다.
- 내용이 있는 단계만 현재 순서대로 다시 번호를 부여합니다.
- 내용이 있는 단계가 하나도 없을 때만 조리 단계 입력 안내와 함께 저장을 막습니다.
- 저장에 실패해도 AI Review 화면과 현재 편집값을 그대로 유지합니다.
- 저장 성공이 확인되기 전에는 완료 레시피로 전환하지 않습니다.
- 입력 조건 문제는 해당 필드 가까이에 이유와 수정 행동을 표시합니다.
- 로컬 저장소 오류는 `레시피를 저장하지 못했어요`와 `다시 저장`을 제공합니다.
- 사용자가 `다시 저장`하기 전까지 현재 Review를 계속 수정하거나 임시 저장할 수 있습니다.
- 같은 진행 기록 식별자를 사용해 다시 저장하더라도 완료 레시피가 중복 생성되지 않게 합니다.
- 앱이 종료되면 마지막으로 성공한 임시 저장 시점까지만 복구합니다.

AI 정리 실패 정책:

- AI 정리 요청마다 고유 식별자를 부여하고 처리 중 상태를 로컬에 저장합니다.
- 처리 중에는 같은 진행 기록의 `AI 정리하기` 중복 실행을 막습니다.
- 요청에 사용한 STEP Preview snapshot은 처리 완료 전까지 추가·삭제할 수 없게 잠급니다.
- Home 카드는 `AI 정리 중` 상태로 표시하고 사용자는 다른 진행·완료 레시피를 자유롭게 사용할 수 있습니다.
- AI 정리 시작 즉시 진행 상태를 표시합니다.
- 10초가 지나면 `조금 더 시간이 걸리고 있어요. 다른 화면을 이용해도 정리는 계속돼요`를 표시합니다.
- 실패로 판단할 timeout 값은 AI 모델과 Backend가 확정된 뒤 실제 지연시간을 측정해 정합니다.
- 첫 출시에서는 AI 정리 취소 기능을 제공하지 않습니다.
- 성공하면 AI Review로 전환하고 실패하면 잠금을 해제해 STEP Preview를 다시 수정할 수 있게 합니다.
- 앱이 백그라운드로 이동해도 서버 요청을 자동 취소하지 않습니다.
- 앱으로 돌아오거나 재실행하면 같은 요청 식별자로 결과를 다시 확인합니다.
- 같은 요청 결과로 AI Review가 중복 생성되지 않게 합니다.
- 앱을 사용하는 동안 완료되면 `레시피 정리가 완료됐어요` 배너를 표시하고, 배너를 누르면 해당 AI Review로 이동합니다.
- 자동으로 현재 화면을 전환하지 않습니다.
- Home 카드는 `검토 준비됨` 상태로 갱신합니다.
- 첫 출시에서는 AI 정리 완료를 위한 로컬 알림과 APNs 원격 푸시를 제공하지 않습니다.
- 실제 사용에서 백그라운드 이탈 필요성이 확인되면 레시피 내용을 포함하지 않는 APNs 완료 알림을 후속 검토합니다.
- 결과를 확인할 수 없거나 요청이 실패하면 STEP Preview를 유지하고 `다시 정리하기`를 제공합니다.
- 오프라인에서도 `AI 정리하기` 버튼을 숨기거나 비활성화하지 않습니다.
- 오프라인에서 누르면 `AI 정리에는 인터넷 연결이 필요해요`를 표시하고 STEP Preview에 머무릅니다.
- 연결이 복구돼도 자동으로 AI를 호출하지 않고 사용자가 다시 `AI 정리하기`를 선택합니다.
- 어떤 실패에서도 STEP Preview 텍스트를 보존합니다.
- Backend는 빈 입력, 네트워크, 시간 초과, 서비스 장애, 응답 형식, 처리 한도와 이용량 상태를 내부 오류 코드로 구분합니다.
- 앱은 사용자에게 실패 원인과 해결 행동을 이해하기 쉬운 문구로 표시합니다.
- 내용 부족이나 AI의 낮은 확신은 실패가 아니라 `AI 추정` 또는 `누락`이 포함된 Review로 처리합니다.
- AI 정리 실패를 자동 재처리하지 않습니다.
- 사용자가 `다시 정리하기` 또는 `기록으로 돌아가기`를 선택합니다.
- AI 제공자, 모델, 상태 코드와 서버 내부 정보는 사용자에게 노출하지 않습니다.
- 오류 로그에는 사용자 STEP 본문이나 레시피 내용을 남기지 않습니다.

## 11. Draft와 Home Specification

레시피 상태:

```text
STEP Preview 진행 중
-> AI Review 진행 중
-> 완료 레시피
```

- 여러 개의 진행 중 레시피를 개수 제한 없이 허용하되 한 번에 하나만 화면에서 편집합니다.
- Home의 `10초 요리 기록 시작`은 새 진행 기록을 만들고 기존 진행 기록은 그대로 보존합니다.
- Home은 진행 기록과 완료 레시피를 별도 영역으로 분리하지 않고 하나의 레시피 목록으로 표시합니다.
- Home의 `최근 레시피`는 진행·완료 상태를 섞어 마지막 활동 시간순 최대 3개까지 표시합니다.
- AI 정리 완료, STEP 변경과 AI Review 임시 저장은 최근 활동 시간에 반영합니다.
- 나머지 기록과 레시피는 `전체 보기`에서 확인합니다.
- 카드는 현재 상태를 다르게 표시합니다.
- STEP Preview 단계 카드를 누르면 마지막 STEP 상태로 이동합니다.
- AI Review 단계 카드를 누르면 마지막 임시 저장 상태로 이동합니다.
- 완료 카드를 누르면 Recipe Detail로 이동합니다.
- 제목이 없는 STEP Preview 초안은 `작성 중인 요리`와 날짜·시간으로 구분합니다.
- 진행 기록 전체 삭제는 카드의 `⋯` 메뉴와 확인창을 거친 뒤 영구 삭제하며 복구를 지원하지 않습니다.
- 오래된 진행 기록을 자동 삭제하지 않습니다.

상태별 Home 카드:

- STEP Preview: `기록 중`, `작성 중인 요리`, STEP 개수와 마지막 활동 시간을 표시합니다.
- AI 처리 중: `AI 정리 중`, STEP 개수와 마지막 활동 시간을 표시합니다.
- AI Review: `검토 필요`, AI가 생성한 제목, 주요 재료와 마지막 활동 시간을 표시합니다.
- 완료 레시피: 제목, 주요 재료 최대 3개, 예상 시간과 단계 수를 표시합니다.
- 완료 카드에는 별도의 `완료` 배지를 표시하지 않습니다.

전체 보기 검색:

- Home의 `전체 보기`에서 제목·재료가 생성된 AI Review 진행 기록과 완료 레시피를 기기 내부에서 검색합니다.
- 아직 제목과 재료가 없는 STEP Preview 진행 기록은 검색 대상에서 제외합니다.
- 검색어와 레시피 내용을 서버나 AI로 전송하지 않습니다.
- 입력과 동시에 결과를 갱신하고 검색어 지우기를 제공합니다.
- 결과가 없으면 `일치하는 레시피가 없어요`를 표시합니다.
- 검색하지 않을 때는 마지막 활동 시간순으로 정렬합니다.
- 검색 중에는 제목 일치를 재료명 일치보다 먼저 표시하고, 같은 조건에서는 마지막 활동 시간순으로 정렬합니다.
- 첫 출시에서는 별도의 정렬·필터 메뉴를 제공하지 않습니다.
- 의미 기반 검색, 오타 교정과 조리 단계·메모 본문 검색은 첫 출시에서 제외합니다.

## 12. 로컬 데이터 보호와 백업

저장 원칙:

- 첫 출시는 계정 없이 진행 기록과 완료 레시피를 사용 중인 기기 내부에만 저장합니다.
- 앱을 정상 종료하거나 업데이트해도 기존 로컬 데이터를 유지합니다.
- 사용자가 삭제하지 않은 진행 기록과 완료 레시피를 앱이 보관 기간이나 개수에 따라 자동 삭제하지 않습니다.

복구 경계:

- CookLog 자체 서버 동기화, 클라우드 백업, 기기 간 동기화와 레시피 내보내기는 첫 출시에서 제공하지 않습니다.
- 앱 삭제, 기기 초기화·분실 또는 로컬 저장소 손상 시 데이터가 유실될 수 있으며 CookLog가 복구를 보장하지 않습니다.
- 운영체제의 기기 백업으로 데이터가 복원될 가능성이 있더라도 CookLog 기능으로 보장하거나 백업 완료 상태로 표시하지 않습니다.

사용자 안내:

- 상시 경고 배너로 기록 경험을 방해하지 않습니다.
- 사용자가 확인할 수 있는 `데이터 보관 안내`에 로컬 저장 범위와 앱 삭제·기기 변경 시 유실 가능성을 명확히 표시합니다.
- 영구 삭제 확인창은 해당 기록의 복구 불가를 별도로 안내합니다.

후속 확장:

- 계정과 클라우드 동기화는 여러 기기 사용과 데이터 복구 필요성이 검증된 뒤 검토합니다.
- 사용자가 직접 보관할 수 있는 레시피 내보내기는 클라우드 동기화와 분리해 후속 우선순위를 평가합니다.

## 13. 개인정보와 서버 데이터 보관

원본 음성:

- 원본 음성은 Apple 기기 내 STT 처리와 같은 adapter의 복구 가능한 기술 오류 1회 재처리에만 사용합니다.
- 첫 출시 기본 경로에서는 원본 음성을 Backend나 외부 STT 제공업체로 전송하지 않습니다.
- 앱의 임시 음성 사본은 처리 성공, 최종 실패 또는 재처리가 끝나면 즉시 삭제합니다.
- 비정상 종료나 정리 작업 실패로 앱 내부에 남은 임시 음성도 생성 후 최대 1시간 안에 자동 삭제합니다.
- Backend 음성 사본의 즉시 삭제·최대 1시간 TTL은 향후 원격 STT adapter를 별도 제품 정책과 비용 승인으로 활성화할 때만 적용합니다.
- 음성을 장기 저장소, 운영 DB, 분석 도구와 오류 로그에 기록하지 않습니다.

STT·AI 콘텐츠:

- STEP Preview, STT 텍스트, AI 입력과 AI 결과는 처리 목적 외에 서버에 영구 저장하지 않습니다.
- 앱 백그라운드·재실행 후 동일 AI 요청 결과를 복구하기 위한 암호화된 임시 콘텐츠 캐시만 허용합니다.
- 복구 캐시는 앱이 결과 수신을 확인하면 즉시 삭제하고, 수신 확인이 없어도 생성 후 최대 24시간 안에 자동 삭제합니다.
- 사용자 콘텐츠를 광고, 모델 학습 또는 별도 제품 개선 데이터셋으로 사용하지 않습니다.

운영 메타데이터와 분석:

- 요청 식별자, 요청 시각, 성공 여부, 오류 범주, 처리 지연시간과 사용량·비용처럼 콘텐츠가 없는 최소 운영 메타데이터만 수집합니다.
- 원시 운영 메타데이터와 원시 분석 이벤트는 최대 30일 보관한 뒤 삭제하거나 개인·요청 단위로 되돌릴 수 없는 통계로 집계합니다.
- 레시피 제목, 재료, 조리 단계, 메모, 검색어, 음성, STT 본문과 AI 결과 본문은 운영·분석·오류 로그에서 제외합니다.
- 광고 추적용 식별자를 수집하지 않고 기능 사용 흐름과 실패율 측정에 필요한 이벤트만 사용합니다.

외부 처리업체와 출시 조건:

- 외부 AI 제공업체에서 모델 학습 사용을 비활성화하고 제공되는 범위에서 가장 짧은 보관 설정을 사용합니다.
- 원격 STT adapter를 향후 활성화할 때도 같은 기준을 적용하며, 실제 학습 사용 여부, 데이터 보관 기간, 처리 지역과 삭제 설정을 활성화 전에 검증합니다.
- 제공업체가 보관을 완전히 비활성화할 수 없다면 실제 조건을 개인정보처리방침에 명시하고 Product Owner 승인 없이 이 기준보다 긴 보관을 허용하지 않습니다.
- 첫 실서비스 출시 전 개인정보처리방침에 처리 목적, 전달 대상, 보관 기간과 삭제 원칙을 사용자가 이해할 수 있게 공개합니다.

## 14. 서비스 장애와 사용자 지원

장애 구분과 안내:

- 앱과 Backend는 마이크·녹음·기기 내 STT, 인터넷 연결, CookLog Backend, 외부 AI와 로컬 저장 실패를 내부적으로 구분합니다.
- 사용자에게는 내부 오류 코드, 제공업체명과 서버 세부 정보를 노출하지 않고 `인터넷 연결을 확인해주세요` 또는 `현재 음성 변환을 사용할 수 없어요`처럼 원인 범주와 다음 행동을 안내합니다.
- 장애 안내는 현재 화면이나 Home의 짧은 상태로 제공하고 푸시 알림이나 자동 화면 이동을 사용하지 않습니다.

기능별 처리:

- 기기 내 STT가 같은 adapter의 1회 자동 재처리 후 최종 실패하면 원격 STT로 자동 전환하지 않습니다. 새 STEP Preview를 만들지 않고 원본 음성을 삭제한 뒤 `다시 기록하기`를 제공합니다.
- AI 정리가 실패하면 기존 STEP Preview와 진행 기록을 보존하고 `다시 정리하기`와 `기록으로 돌아가기`를 제공합니다.
- 실패 원인이 해소돼도 녹음, STT와 AI 정리를 자동 실행하지 않고 사용자가 다시 시작합니다.
- 장애 중에도 진행·완료 레시피 조회와 편집, 로컬 검색, 로컬 저장, 버튼 기반 Audio Guide와 로컬 TTS를 계속 사용할 수 있어야 합니다.
- 로컬 저장 실패는 온라인 장애와 구분하고 현재 편집값을 유지한 채 `다시 저장`을 제공합니다.

첫 출시 운영 범위:

- 별도 서비스 상태 페이지, 실시간 채팅과 24시간 고객지원을 제공하지 않습니다.
- 사용자가 확인할 수 있는 `앱 정보`에 이메일 `문의하기`, 개인정보처리방침, 이용약관과 데이터 보관 안내를 제공합니다.
- 문의 이메일에 음성, STT 본문, 레시피 내용과 검색어를 자동 첨부하지 않습니다.
- 문의에 필요한 앱 버전과 사용자가 직접 선택한 비콘텐츠 진단 정보만 제공할 수 있습니다.

## 15. Recipe Detail Specification

표시 항목:

- 제목
- 재료
- 조리순서
- 메모
- 예상시간

CTA:

- 오디오 가이드 시작

완료 레시피 정책:

- Recipe Detail의 `⋯` 메뉴에서 `레시피 수정`으로 진입합니다.
- 수정 화면은 AI Review와 같은 편집 폼을 사용하되 `AI DRAFT`와 임시 저장을 표시하지 않습니다.
- `수정 완료`를 누르면 AI를 다시 호출하지 않고 기존 완료 레시피를 업데이트합니다.
- 이전 버전과 수정 이력은 첫 출시 범위에서 보관하지 않습니다.
- 완료 레시피 삭제는 Recipe Detail의 `⋯` 메뉴에서만 제공합니다.
- 복구 불가 안내를 포함한 확인창 후 즉시 영구 삭제합니다.
- 휴지통, 최근 삭제와 삭제 복구는 첫 출시 범위에서 지원하지 않습니다.

## 16. Audio Guide Specification

버튼 기반 기본 동작:

- 재생
- 일시정지
- 이전 단계
- 다음 단계
- 현재 단계 다시 듣기

진행 정책:

- 화면 진입 시 자동 재생하지 않고 1단계를 준비 상태로 표시합니다.
- 한 단계를 읽은 뒤 자동으로 다음 단계로 넘어가지 않고 사용자의 다음 행동을 기다립니다.
- 일시정지는 읽던 단어가 끝나는 경계에서 멈추고 재생은 멈춘 위치부터 이어갑니다.
- 다시 듣기는 현재 단계를 처음부터 읽습니다.
- 다음·이전은 이동한 단계를 처음부터 읽습니다.
- 마지막 단계가 끝나도 화면을 유지하며, 마지막 단계에서 다음을 실행하면 `마지막 단계예요`라고 안내합니다.
- 사용자가 `가이드 종료`를 누르면 Recipe Detail로 돌아갑니다.

첫 App Store 공개 출시 핸즈프리 명령:

- 다음
- 이전
- 멈춰
- 계속
- 다시 들려줘
- 재료 알려줘
- 핸즈프리 종료

핸즈프리 정책:

- 호출어는 사용하지 않습니다.
- Audio Guide 진입 시 핸즈프리는 꺼져 있으며 사용자가 `핸즈프리 시작`을 눌러 활성화합니다.
- 별도의 음성인식 또는 마이크 권한이 필요하면 사용자가 처음 `핸즈프리 시작`을 누른 시점에 사용 이유를 설명한 뒤 요청합니다.
- 권한을 거부하면 핸즈프리만 비활성화하고 Audio Guide와 모든 버튼 조작은 유지합니다.
- 거부된 상태에서 다시 시작하면 권한 안내와 `설정으로 이동`을 제공하고 시스템 권한창을 반복 호출하지 않습니다.
- 사용자가 종료하거나 Audio Guide를 나갈 때까지 유지하고, 일시정지 중에도 명령을 듣습니다.
- TTS가 단계를 읽는 중에도 `멈춰`를 포함한 음성 명령을 인식할 수 있어야 합니다.
- `핸즈프리 종료`는 마이크만 끄고 현재 오디오 재생과 버튼 조작은 유지합니다.
- Audio Guide 밖에서는 음성 명령이 작동하지 않습니다.
- 불확실한 명령은 실행하지 않으며 음성 인식 실패가 재생 상태를 초기화하지 않습니다.
- 음성 명령을 사용할 수 없어도 모든 행동을 버튼으로 이어갈 수 있습니다.
- 매번 확인 음성을 재생하지 않고 실제 단계 재생, 상태 강조와 필요한 경우 짧은 효과음으로 결과를 알립니다.
- Audio Guide 화면이 열려 있는 동안 자동 화면 잠금을 막습니다.
- 사용자가 직접 잠그거나 앱을 백그라운드로 보내면 핸즈프리를 종료하고 복귀 후 자동 재활성화하지 않습니다.

재료 듣기와 TTS:

- 재료 목록을 자동 재생하지 않고 `재료 듣기` 버튼과 `재료 알려줘` 명령으로 제공합니다.
- 재료 낭독은 현재 단계를 변경하지 않으며 종료 후 현재 단계를 일시정지 상태로 유지합니다.
- 화면 데이터는 유지하고 음성 출력 직전에 지원하는 숫자와 단위만 규칙으로 자연스럽게 변환합니다.
- 불확실한 표현은 원문 그대로 읽고 단위를 임의로 환산하거나 LLM으로 새 문장을 만들지 않습니다.
- 초기 지원 대상은 `g`, `kg`, `ml`, `L`, `개`, `큰술`, `작은술`, `분`, `시간`, `°C` 등 일반 요리 단위입니다.
- 읽기 속도는 `느리게`, `보통`, `빠르게` 세 단계로 제공하고 기본값은 `보통`입니다.
- 사용자가 선택한 속도는 다음 Audio Guide에도 유지하며 재생 중 변경하면 현재 문장이 끝난 뒤 적용합니다.

오디오 중단:

- 전화, Siri와 다른 오디오가 시작되면 현재 위치에서 일시정지합니다.
- 중단이 끝나도 자동 재생하거나 핸즈프리를 자동 재활성화하지 않습니다.
- Bluetooth 또는 이어폰 연결이 끊겨도 기기 스피커로 갑자기 재생하지 않고 일시정지합니다.
- 현재 단계와 재생 위치를 유지하고 사용자가 버튼이나 명령으로 이어갑니다.

- 기록 시작부터 STT, STEP Preview, AI 정리, AI Review, 최종 저장, 앱 재실행, Recipe Detail과 Audio Guide까지 핵심 흐름을 3회 연속 완료합니다.
- 일반 실내 음성 5회와 실제 조리 소음이 있는 환경의 음성 5회에서 핵심 행동이 이해 가능한 STEP Preview를 합계 8회 이상 생성합니다.
- 서로 다른 STEP 기록 5개를 AI로 정리해 모두 최초 요청 또는 사용자의 1회 `다시 정리하기` 안에 Review로 진입하고 기록 손실이 없어야 합니다.
- AI Review 5개에서 기록에 없는 안전 관련 재료·온도·시간·조리법의 창작이 0건이어야 합니다.
- 핸즈프리 7개 명령을 조리 소음 환경에서 각각 최소 1회 성공시키고, 인식 실패 상태에서 버튼으로 같은 행동을 이어가는 fallback을 1회 확인합니다.
- STEP Preview 자동 저장, AI Review 임시 저장, AI 처리 중 앱 재실행, 오프라인 안내와 AI 실패 후 다시 정리하기를 각각 최소 1회 확인하고 기록 손실이 없어야 합니다.
- 출시 대상 빌드와 필수 CI 검사가 통과하고 미해결 P0·P1 결함이 0건이어야 합니다.
- 위 기준은 최소 출시 차단 기준이며 통계적 정확도나 대규모 사용성 검증을 의미하지 않습니다. 출시 후 실제 성공률과 실패율로 보강합니다.

## 19. Product Principle

1. MVP 기록은 10초 고정 단위로 끝납니다.
2. 사용자는 레시피를 작성하지 않습니다.
3. 사용자는 요리만 합니다.
4. 음성은 입력 도구이며 보존되는 기록은 텍스트입니다.
5. AI는 기록을 구조화하고 기록에 없는 내용을 창작하지 않습니다.
6. STEP Preview는 원문 기록, AI Review는 구조화와 검토, Recipe Detail은 최종 완료 상태입니다.
7. 진행 중 기록은 복구 가능해야 하고 최종 저장은 사용자의 명시적 행동으로 완료합니다.
8. 저장된 레시피는 단계별 오디오로 소비합니다.
9. 버튼은 항상 사용 가능하며 핸즈프리는 첫 공개 출시의 핵심 경험입니다.
10. 첫 출시는 로컬 저장을 우선하며 제공하지 않는 백업이나 복구를 약속하지 않습니다.
11. 음성·레시피 콘텐츠는 기능 처리에 필요한 최소 시간만 서버에서 사용하고 운영·분석 로그에 남기지 않습니다.
12. 온라인 장애는 로컬 기록 사용을 막지 않으며 실패한 행동은 사용자가 명시적으로 다시 실행합니다.
