# CookLog 팝 키치 레시피 클럽 UX 구조·핵심 기능 계획

작성일: 2026-08-12
Task: `T-20260812-002`
상태: 실행 초안
대상: 20~30대 자취생 — 요리를 자주 기록하지 않지만, 맛있게 된 한 끼는 다음에도 쉽게 재현하고 싶은 사용자

## 1. 이번 재기획의 결론

CookLog는 **AI가 요리를 추천해 주는 앱**이 아니라, “방금 한 요리를 짧게 말로 남기면 다음번에 다시 만들 수 있게 정리해 주는 개인 요리책”이다.

팝 키치 레시피 클럽은 이 기능을 더 빠르고 재미있게 보이게 하는 표현 방식이다. 따라서 UI의 우선순위는 다음과 같다.

1. 지금 할 행동 하나를 먼저 보인다.
2. 긴 설명 대신 상태·다음 행동·보존 여부를 짧게 알려준다.
3. AI는 앞에 서는 챗봇이 아니라 기록을 정리해 주는 작은 도우미다.
4. 조리 중 화면은 귀엽더라도 안전하고 조작하기 쉬워야 한다.
5. 완료한 레시피는 “저장된 데이터”보다 “내가 다시 꺼내 쓰는 요리책의 한 페이지”처럼 보여야 한다.

## 2. 변경하지 않는 제품 계약

아래는 디자인·정보 구조가 바뀌어도 유지한다.

- 첫 실행은 별도 온보딩 없이 Home으로 진입한다.
- 새 기록은 고정 10초 음성 기록이며, 기존 진행 기록은 보존한다.
- STEP Preview는 사용자의 음성을 원문 중심으로 쌓고, 삭제·되돌리기와 자동 저장을 유지한다.
- AI는 STEP을 제목·재료·순서로 구조화할 뿐, 기록에 없는 조리법을 창작하지 않는다.
- AI Review는 임시 저장·이어서 작성·최종 저장을 유지한다.
- 진행 기록과 완료 레시피는 최근 활동순으로 보며, 로컬 검색·로컬 저장·버튼 기반 Audio Guide는 온라인 AI 장애에도 유지한다.
- 완료 레시피는 수정·영구 삭제·Audio Guide 진입을 유지한다.
- Audio Guide는 버튼으로 완결되며, 핸즈프리는 사용자가 명시적으로 시작한 경우에만 보조한다.
- 모든 화면은 `390×844pt` 기본, `375×667pt` 작은 화면, Light/Dark, Accessibility 3, 최소 44pt 터치 영역을 지킨다.

## 5. 핵심 사용자 여정과 상호작용 원칙

### A. 오늘 만든 요리를 남긴다

`Home → 중앙 기록 CTA → 10초 녹음 → STEP Preview 누적 → 레시피로 정리 → AI Review → 레시피 저장`

- Home에서는 새 기록과 최근 카드 이외의 결정을 요구하지 않는다.
- 녹음 중에는 남은 시간과 취소 불가 정책을 명확히 보이되, 기능 설명은 접는다.
- STEP은 “AI가 만든 요리”가 아닌 “내가 말한 기록”으로 보인다.
- `AI 정리하기`보다 결과 중심의 `레시피로 정리`를 우선 카피로 사용한다. 내부적으로는 AI 정리 계약을 그대로 유지한다.
- AI Review에서는 `저장`을 앞세우되, 추정값의 확인 여부를 사용자가 통제한다.

### B. 지난 요리를 다시 만든다

`Home 최근 카드 또는 Library 검색 → Recipe Detail → Audio Guide`

- Home은 최대 3개만 보여 주고, 더 찾는 행동은 `전체 요리책 보기`로 명확히 분리한다.
- Recipe Detail의 첫 CTA는 `다시 요리하기` 맥락의 Audio Guide 진입이다.
- Player는 한 단계씩 진행한다. “다음”은 자동 진행의 의미가 아니라 사용자의 다음 행동이다.

### C. 처리·권한·저장 실패에서 회복한다

- 실패는 전체 기능을 막는 모달보다 현재 위치의 짧은 상태 모듈로 우선 보여 준다.
- 문구 구조는 항상 `무슨 일인지 → 남아 있는 것 → 지금 할 수 있는 행동` 순서다.
- 예: `레시피 정리가 멈췄어요 / 말한 기록은 남아 있어요 / 다시 정리하기`.
- 권한 거부 시에는 설정 이동과 닫기를 제공하지만, Home·Library·Player를 막지 않는다.

## 6. 화면별 UX 레이아웃 명세

### 6.1 Home — 오늘의 기록 시작점

390×844pt의 콘텐츠 순서:

```text
[상단] CookLog / 앱 정보 / 전체 요리책
[브랜드] 짧은 오늘의 라벨 + 큰 CookLog 워드마크 + 작은 그래픽
[주 행동] 원형 마이크 CTA + “바로 말하고 기록하기”
[상태] AI 완료·네트워크 오류가 있을 때만 한 줄 행동 모듈
[최근] 오늘 다시 꺼낼 요리 3개 + 전체 요리책 보기
[보조] AI는 기록을 레시피로 정리한다는 작은 팁
```

- 카드의 상태 라벨은 `기록 중`, `정리 중`, `검토 필요`처럼 현재 다음 행동을 직접 말한다.
- 완료 레시피에는 별도 `완료` 라벨을 붙이지 않는다. 제목·재료·시간/단계가 곧 완성 신호다.
- 최근 카드는 390pt에서 2열을 기본으로 하되, 3번째 카드는 다음 행의 시작으로 둔다. 375pt에서는 카드 최소 폭을 지키며 2열을 유지하거나, 긴 제목·접근성 글자 크기에는 1열로 안전하게 전환한다.
- T-008의 현재 원형 CTA·큰 워드마크·짧은 카피 방향과 일치한다. 기능·정보 구조를 새로 변경해야 할 후보는 T-008 완료본 검토 뒤 별도 재작업으로 분리한다.

### 6.2 Library — 내 요리책 인덱스

```text
[상단] 뒤로가기 / 전체 요리책
[도입] “내가 만든 요리들” 한 줄 제목
[검색] 제목·재료 검색 / 로컬 검색 안내
[결과] 최근 활동순 또는 제목 우선 검색 결과
[빈 상태] 첫 기록 시작 또는 검색어 지우기
```

- Home처럼 브랜드 Hero를 반복하지 않는다.
- 검색 안내는 개인정보 약속을 보존하되, 검색 입력과 가까운 한 줄로 둔다.
- 진행 레시피와 완료 레시피는 상태 라벨·다음 목적지로 구분한다. 새 필터, 의미 검색, 단계 본문 검색은 추가하지 않는다.

### 6.3 Cooking Log — 요리 중 기록 모드

```text
[상단] 뒤로가기 / 요리 기록 / 현재 상태
[기록 흐름] “지금 한 일을 짧게 말해요” + 녹음·변환 상태
[STEP 목록] 시간순 STEP Preview / 삭제·되돌리기
[다음 행동] STEP이 있을 때 레시피로 정리
[하단 고정] 10초 기록 CTA
```

- 화면의 주인공은 큰 타이포나 장식이 아니라 현재 기록 행동이다.
- `STEP Preview`는 사용자 친화 카피로 `말한 요리 순서`를 우선 표기하고, 필요 시 작은 보조 라벨로 원래 용어를 유지한다.
- 고정 CTA와 `레시피로 정리` CTA가 동시에 경쟁하지 않게, STEP이 있을 때도 녹음은 하단에, 정리는 목록 끝에 배치한다.
- 녹음/변환/AI 처리 중에는 카드의 편집 가능 여부와 보존 상태를 색만으로 구분하지 않는다.

### 6.4 AI Review — 내 레시피로 다듬는 편집 모드

```text
[상단] 뒤로가기 / 레시피 다듬기
[표지] 제목 + “말한 내용을 정리했어요” + 신뢰 라벨
[재료] 재료와 수량
[순서] 큰 단계 카드 / 추가·삭제·이동
[보조] 예상 시간, 메모
[하단] 임시 저장 / 레시피 저장
```

- 화면명과 CTA는 `AI Review`, `AI 정리`보다 `레시피 다듬기`, `레시피 저장`을 우선 사용한다.
- `AI 추정`, `누락`, 확정은 필드 단위 라벨로 표시한다. AI 캐릭터·대화형 말풍선은 사용하지 않는다.
- `임시 저장`은 보조 버튼이며, 입력이 남아 있을 때 이탈 확인에서 더 중요해진다.
- 저장 실패는 해당 입력 필드 또는 하단 저장 영역 가까이에 보여 준다.

### 6.5 Recipe Detail — 다시 꺼내 보는 한 페이지

```text
[상단] 뒤로가기 / 더보기
[표지] 레시피 제목 + 시간·재료·단계 요약
[주 행동] 오디오 가이드 시작
[본문] 재료 → 조리 순서 → 메모
```

- 완료 레시피는 차분한 요리책 페이지이고, 색상은 정보 구분·주 CTA에만 쓴다.
- 수정과 삭제는 더보기 메뉴에 둬 `다시 요리하기`보다 앞서지 않게 한다.
- 재료가 없거나 메모가 없을 때는 빈 콘텐츠를 과하게 장식하지 않고 필요한 경우만 생략한다.

### 6.6 Audio Guide — 손이 바쁠 때 한 단계에 집중하는 모드

```text
[상단] 종료
[진행] STEP n / 전체 단계
[중앙] 현재 한 단계 문장
[보조] 핸즈프리 상태, 재료 듣기, 속도
[하단 고정] 이전 / 다시 / 재생·정지 / 다음
```

- 장식은 최소화한다. 현재 단계 텍스트·재생 상태·버튼의 대비가 최우선이다.
- 핸즈프리는 `켜짐/꺼짐`과 권한 상태를 명확히 보여 주되, 버튼 기반 조작보다 우선하지 않는다.
- 오류나 불확실한 명령은 현재 단계와 재생 위치를 보존하고, 한 행동만 제안한다.

### 6.7 App Info — 신뢰와 도움말

```text
[상단] 뒤로가기 / 앱 정보
[요약] 내 기록은 이 기기에 저장됨
[목록] 문의 / 개인정보 / 이용약관 / 데이터 보관
[주의] 백업·동기화 미제공은 상세 페이지에서 명확히 설명
```

- App Info는 팝 키치 장식보다 읽기 쉬운 인덱스와 신뢰 문구를 우선한다.
- 데이터 보관·법적 문서의 긴 설명은 상세 페이지에서만 제공한다.

## 7. 공통 카피와 시각 규칙

| 기존 성격 | 권장 UX 표현 | 원칙 |
|---|---|---|
| `STEP Preview` | `말한 요리 순서` | 내부 용어보다 사용자가 한 행동을 먼저 말한다. |
| `AI Review` | `레시피 다듬기` | AI가 아닌 사용자의 검토와 저장을 주어로 둔다. |
| `AI 정리하기` | `레시피로 정리` | AI는 결과를 돕는 수단으로만 노출한다. |
| `10초 요리 기록 시작` | `10초 말하고 기록하기` 또는 `요리 기록 시작` | 화면의 맥락에 따라 짧게 쓴다. 고정 10초 정책은 첫 안내와 녹음 화면에 명시한다. |
| 일반 안내 문단 | 한 줄 상태 + 하나의 행동 | 상세 설명은 사용자가 필요한 때만 펼친다. |

- 크림 바탕, 토마토 레드 CTA, 버터 옐로·코발트 블루 포인트, 강한 디스플레이 타이포를 사용한다.
- 스티커·테이프·낙서는 화면당 한두 개의 위계 강화 장치로만 쓴다.
- 토마토 레드는 시작·저장·재생처럼 “지금 하라”는 행동에만 쓴다.
- 오류·권한·삭제·조리 중 Player에서는 장식 밀도를 낮추고 정보와 동작의 명확성을 우선한다.
- Light/Dark에서 의미 토큰과 상태 라벨을 유지하며, 색만으로 상태를 전달하지 않는다.

## 8. Design Lead handoff

- 현재 승인 범위의 큰 워드마크, 중앙 원형 기록 CTA, 최근 카드, 비챗봇 AI 도우미는 이 문서의 Home 원칙과 정렬된다.

- Product Owner 판단이 필요한 Home 변경 후보는 다음 두 가지다.
  1. 최근 카드 영역의 라벨을 `최근 레시피`에서 `오늘 다시 꺼낼 요리`로 바꿀지
  2. `전체 보기`를 헤더 아이콘보다 카드 영역의 텍스트 액션으로 승격할지
- 둘 다 기능/routing 변경 없이 가능한 정보 구조 보정이다. T-008 결과 검토 뒤 별도 micro-rework로 결정한다.

### T-005 Log·Review·Detail

- 이 문서의 6.3~6.5 레이아웃과 7절 카피 원칙을 화면 원본 적용의 기준으로 사용한다.

- T-005 scope 전환 시 T-20260812-002 완료 및 Product Owner의 기능 후보 결정 여부를 확인한다.

### T-006 Player·Info·오류

- App Info는 신뢰·보관·법적 정보의 가독성을 우선한다.

### T-007 통합 Design QA

- 82개 상태의 행동·데이터 보존·권한·오류 계약을 유지했는지 확인한다.
